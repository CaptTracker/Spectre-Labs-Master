# Vehicle, missile and overlay rendering (slice key: vehicle-render)

Ported from `vehicle/model/**`, `vehicle/render/**` (with `render/vehicle`, `render/missile`) of Ancient Warfare 2 (1.12.2-2.7.0.1038). Nothing was compiled or run; every
Minecraft and NeoForge name was checked against `analysis/mc-sources` (ModelPart, LayerDefinition, EntityRenderer, EntityRenderersEvent, RegisterGuiLayersEvent, LayeredDraw,
RenderLevelStageEvent, LevelRenderer.renderLineBox, RenderType, VertexConsumer, FastColor, Camera, DeltaTracker).

## Files (package `io.github.capttracker.ancientwarfarevehicle`)

- `client/model/AwPartModel` (base: baked root plus `renderToBuffer`), 20 generated models: `ModelCatapultStandFixed`, `ModelCatapultStandTurret`, `ModelCatapultMobileFixed`,
  `ModelCatapultMobileTurret`, `ModelBallistaStand`, `ModelBallistaMobile`, `ModelBatteringRam`, `ModelCannonStandFixed`, `ModelCannonStandTurret`, `ModelCannonMobileFixed`,
  `ModelHwacha`, `ModelTrebuchetStandFixed`, `ModelTrebuchetStandTurret`, `ModelTrebuchetMobileFixed`, `ModelChestCart`, `ModelBoatBallista`, `ModelBoatCatapult`,
  `ModelBoatTransport` and the missile models `ModelArrow2`, `ModelShot`. Each has `LAYER` (`ancientwarfarevehicle:<snake name>#main`), `createLayer()` and the original setters.
  1173 boxes. Generated by `analysis/port/vehicle_render_models.py` (`python -I`; strict line grammar, stops on any statement it does not know, re-run reproduces the files byte for byte).
- `client/render/VehicleRenderer` (RenderVehicle: one `EntityRenderer`, texture of the material level, hit tint, first-person ghost, name plate),
  `VehicleModelDelegate` + `VehicleModels` (the 19 `RenderVehicleBase` classes as one lambda per type, indexed by the global type index; verified line by line against the originals),
  `MissileRenderer` (RenderMissile, RenderMissileBase, RenderArrow, RenderShot), `VehicleOverlayHud` (RenderOverlay, a GUI layer), `VehicleAimOverlay` (RenderOverlayAdvanced,
  a `RenderLevelStageEvent` listener on the game bus, `@EventBusSubscriber(value = Dist.CLIENT)`).
- `client/VehicleRenderClient`: mod-bus registration of the 20 layer definitions, the two entity renderers (`AwVehicles.VEHICLE`, `AwVehicles.MISSILE`) and the HUD layer
  (`registerAboveAll`, id `ancientwarfarevehicle:vehicle_overlay`).
- Textures: the 75 vehicle textures and 3 ammo textures are already in `assets/ancientwarfarevehicle/textures/model/vehicle/**` (copied by the vehicle-entity and vehicle-missiles
  slices; checked: every `vehicleTexture(name, level)` of the 15 type families has its 5 files). Not copied: `textures/entity/vehicle/ballistaMobile1.png`, `catapultMobileFixed1.png`
  (unreferenced leftovers of the original).
- Lang: `vehicle-render.lang.json` (13 keys, all new: the HUD strings were hard-coded English; the keys are `ancientwarfarevehicle.overlay.*`).

## Wiring needed

None in shared files: both client classes are auto-registered by their `@EventBusSubscriber` annotations. Add the 13 lang keys to `lang/en_us.json`. The module already
depends on Core (`Trig`).

## How it works

- Model conversion: `ModelRenderer` pieces become `PartDefinition`s with the same rotation point, rotation (`setPieceRotation`), texture offset, boxes (6 and 7 argument `addBox`,
  the one `mirror` flag kept) and parent-child nesting, so the transform order (translate, then z-y-x rotation) is the one of 1.12.2. Only the pieces reachable from what the
  original `render()` drew are emitted (none were dropped). A piece drawn both as a root and as a child of an identity parent was emitted once. Setters become `xRot`/`yRot`/`zRot`
  writes (radians through `Trig.toRadians`, unchanged). The models hold animation state, so there is one model instance per renderer and the delegate sets every angle before each draw.
- Transform: translate to the entity (done by the dispatcher), `rotate(yaw, y)`, `scale(-1, -1, 1)`, exactly as `RenderVehicle`. Types sharing a model share the instance
  (both ballista stands, both mobile ballistae, stand-fixed and large trebuchet which is drawn at scale 2.5).
- Turret yaw and pitch terms keep the sign differences of the original delegates (`+ (1 - tick)` for the mobile ballistae and the ballista boat, `- tick` elsewhere). Compare in game.
- Hit feedback: vertex colour (1, 1-p, 1-p) with `p = hitAnimationTicks / 20`. First person ghost (`renderVehiclesInFirstPerson` false, local player drives, first person camera): alpha 0.2 with
  `entityTranslucent`; the hit tint makes it opaque for its duration, as `GlStateManager.color(..., 1)` did.
- Missile: yaw - 90 about y, pitch - 90 about x, scale(-1, -1, 1), then `IAmmo.getRenderScale()`. The arrow model is used for the 9 arrow, bolt and rocket ammo, the shot model for all
  others (the original map had all 51 entries, the same split). The arrow set is built on the first frame because `AmmoRegistry` fills its fields late.
- HUD: same lines and positions (x 10, y 10 to 80), skipped while a screen is open or the GUI is hidden, gated by `clientSettings.renderOverlay` (and `renderAdvOverlay` for the last two lines).
- Aim preview (`clientSettings.renderAdvOverlay`): white line 20 blocks ahead (alpha 0.6), the ballistic or rocket path from the missile offset (rgb 1, 0.4, 0.4, alpha 0.4), for the ram
  the line plus three crossing outline boxes. Drawn after the particles with `RenderType.lines()` relative to the camera, capped at 512 segments, returns early without player, level,
  pose stack or on zero launch speed.

## Changes from 1.12.2

- The name plate uses the vanilla name tag (`renderNameTag`) with the original text (`<type name> <health>/<base health>`) and conditions; the see-through background and double text pass
  of the hand-built quad are the vanilla ones now. Offset is height + 0.75 as before (0.25 added to the vanilla 0.5). `posY > 0` became `y > minBuildHeight` (worlds reach below 0 now).
- Numbers in the HUD are formatted to one decimal (1.12.2 printed raw floats); strings are lang keys.
- Line widths 3 and 4 are the width of vanilla's line shader (not settable per line); the dynamic line is drawn in world coordinates relative to the camera with the interpolated vehicle position
  (1.12.2 used the player's unsmoothed position offset).
- Missile pitch is interpolated (1.12.2 used the raw pitch).
- Fixed an obvious original bug locally: the trajectory loops `while (y >= floor)` never ended for a launch speed of 0 (division by zero for rockets); now capped and guarded.

## Not ported / open

- Original `RenderTools.drawOutlinedBoundingBox` is replaced by `LevelRenderer.renderLineBox`.
- `RenderVehicle` had a field for `renderVehicleNameplateHealth`-less plate formatting through `DecimalFormat("#.#")`; kept, locale dependent.
- Air vehicle branches (throttle HUD, floor at world y 0) are ported but no vehicle type uses an air movement type.
- Vehicle crew and riders are vanilla entities, nothing to render here.

## Unconfirmed API names

None known; all names above were read in the sources. The areas most likely to need a compile fix: `FastColor.ARGB32.color(int, int, int, int)` argument order (a, r, g, b, as read), `Camera.getPosition()`, the `bus` parameter of `EventBusSubscriber` (used like Core does).

## Rework candidates

- Replace the per-type delegate lambdas with a small interface implemented by each model once the sign inconsistencies of the turret terms are compared in game.
- Real item/armor/upgrade visuals (none existed); a shared `AwPartModel` could move to a render library if the structure and NPC modules port their Techne models the same way (the script already works for `structure/model`).
- Vehicle shadows and block-light handling were never implemented in the original (shadow size 0); unchanged.
