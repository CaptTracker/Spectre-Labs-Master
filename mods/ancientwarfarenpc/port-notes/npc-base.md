# NPC module: base slice (npc-base)

Module entry, registration, config, data registries, factions, saved data, network, commands, events, skins, block, recipes, assets and data.
Nothing was compiled; 1.21.1 names were checked against `analysis/mc-sources`. An earlier partial run of this slice had written most of the Java; it was
reviewed against the originals and the sources and kept, with the changes listed under "Changes made in review".

`AwNpcs` registers: the town hall block, item and block entity; 64 items (1.12.2: 58 items + the town hall item block, but the metadata variants
of the bard instrument (4) and the coin (4) are separate items now); 23 entity types (7 player-owned `aw_npc_*`, 15 `faction.*`, and
`no_friendly_fire_potion`, which 1.12.2 never registered); the `order_copy` recipe serializer; the `rides_vehicle` loot condition; the creative tab;
119 sounds. Registry names are the 1.12.2 ones. Item classes are built here with plain `Item.Properties` and a documented constructor signature (see
the Javadoc of `AwNpcs`), which the item slice must provide.

### Data and assets (written by `analysis/port/npc_base_assets.py`, run with `python -I`)

- `data/ancientwarfarenpc/registry/npc/`: `target_lists`, `factions` (44), `faction_npc_defaults` (defaults, NPC subtypes and the 44 factions), `owned_npc_defaults`,
  `faction_trade_lists` (130 lists, 3,604 stacks in the 1.21 item stack format). Conversions: 6 renamed vanilla entity ids (`zombie_pigman`, `villager_golem`,
  ...), attribute names (`generic.maxHealth` -> `generic.max_health`), Java class names of the mounts -> entity ids, `ancientwarfarenpc:bard_instrument`
  -> `bard_instrument_lute`, `minecraft:skull` -> `skeleton_skull`, `ancientwarfare:entities/*` loot tables -> `ancientwarfarenpc:entities/*`, trade stacks
  with damage values and NBT flattened (wool, logs, dyes, fish, flowers, beds, banners, potions, spawn eggs, enchantments, names, dyed colours, coins by metal).
  Stacks of mods that have no 1.21 version (Rustic, Harvestcraft) and of the Structures furniture keep their old ids: they fail to decode and
  `FactionTradeTemplate#isValid` drops those trades, as 1.12.2 dropped unknown items.
- `data/ancientwarfarenpc/loot_table/entities/` (19 faction NPC tables; the siege engineer table uses `ancientwarfarenpc:rides_vehicle` and refers to the
  chest tables `ancientwarfare:chests/ammo_*` and `potion_harmful` of the Structures data slice), `loot_table/blocks/town_hall.json`.
- `data/ancientwarfarenpc/recipe/`: 15 reach weapon recipes, 4 order copy recipes, `recipe/research/` 23 research recipes (Core's converter with
  `research_recipes_npc_items.json`).
- Tags: `ancientwarfarenpc:food_bundles` (the old ore name `foodBundle`), `minecraft:wolf_food` (adds the food bundle), `minecraft:mineable/pickaxe` (adds the town hall).
- `assets/ancientwarfarenpc/`: `sounds.json` + 364 `.ogg` (unchanged), 82 item textures (`textures/item/<name>.png`), 103 item models, town hall block (model, blockstate,
  animated texture), `textures/skin_pack/` (3,606 PNGs; 10 file names with capitals or spaces were renamed to `[a-z0-9_]`), `registry/skin_pack.json`
  (index: 655 NPC types and 1,768 unlisted "custom" skins), `textures/entity/npc/` (default skin and AI icons).
- The spawner item model switches on `custom_model_data` (value `i + 1` = `AwNpcs.SPAWNER_MODEL_VARIANTS[i]`, no component = base icon).

## Wiring needed in shared files

1. `AncientWarfareNPC.java` constructor, before `REG.register(modBus)`:
   ```java
   AwNpcs.load();
   AwNpcs.registerEvents(modBus, container);
   ```
   (`registerEvents` registers config, entity types, recipe serializer, loot condition, payloads, attributes, capabilities, common setup, the five JSON parsers,
   the skin index parser, the compat hooks, the game event handlers and the commands.) Imports: `io.github.capttracker.ancientwarfarenpc.init.AwNpcs`.
2. `lang/en_us.json` of the module: merge `port-notes/npc-base.lang.json` (789 keys; replaces the template's `block...example_block`). The entity names are in both
   forms: `entity.ancientwarfarenpc.<full type>.name` (read by `NpcBase`) and `entity.ancientwarfarenpc.<registry name>` (the entity type description).
3. Core's `RegistryLoader.SERVER` is a data pack reload listener (`AwCoreMisc`) and `RegistryLoader.CLIENT` a resource reload listener (`CoreMiscClient`): both
   already exist. The five NPC parsers are registered on `SERVER`, the skin parser on `CLIENT` (`NpcSkinManager.registerParser`).
4. Installed by other slices (each is a setter, nothing breaks if absent, the feature is just off):
   - item slice: `NpcBridge.setSpawnerStackFactory(...)` (town hall death list and repack need it), `NpcCommand.setCommandedEntitiesProvider(...)` (the baton's
     `getCommandedEntities`), `DataComponents.CUSTOM_MODEL_DATA = new CustomModelData(AwNpcs.getSpawnerModelIndex(variant))` on spawner stacks.
   - menu slice: `NpcBridge.setGuiOpener(...)`, `TownHallBlockEntity.setMenuOpener(...)`.
   - client: `NpcSkinSettings.setPlayerSkinResolver(...)` (player skins by name through the vanilla skin manager), a key handler that calls
     `NpcCommand.handleCommandClient(type, hit)`, a client logout hook that calls `FactionData.resetClientMirror()` and `TeamData.resetClientMirror()`.
   - Structures module (if ever): implement `IStructureProtection` and call `NpcEventHandler.INSTANCE.setStructureProtection(...)`. Without it the structure rules
     (no hostile spawns, locked loot chests, slow digging) are off.
5. `build.gradle` already depends on Core and Vehicles (`RidesVehicleCondition` imports `VehicleBase`).
6. The data components of orders, the spawner and the coin are the item slice's business; the research recipes for the 7 spawner types currently produce the
   spawner with `minecraft:custom_data {npcType, npcSubtype}` (`recipe/research/spawner_*.json`). Change them to the spawner's own component once it exists.

## Changes made in review (of the earlier partial run)

- `TownHallBlockEntity` now implements the entity slice's `ITownHall` (it is what `NpcPlayerOwned` finds with `WorldTools.getTile`), broadcasts to
  `NpcPlayerOwned` directly and builds the death list entry through `NpcBridge.createSpawnerStack`. The premature `ITownHallNpc` interface was removed.
- `NpcCommand` moved from `command` to `npccommand` (the entity slice imports it there) and gives the command to `NpcPlayerOwned#handlePlayerCommand`
  directly (a copy per NPC) instead of through an interface nothing implemented.
- `CommandTeams`: `describe` and `player` accept 0 arguments again (Core's `SimpleSubCommand` requires `getMaxArgs()` otherwise).
- `AwNpcs`: fixed the import of `NpcSiegeEngineer` (it is in `entity.vehicle`), registers the entity slice's payload (`NpcEntityPayloads`), the loot condition,
  the compat hooks, and offers `SPAWNER_MODEL_VARIANTS` / `getSpawnerModelIndex`.
- Added `RidesVehicleCondition` (the 1.12.2 entity property of the siege engineer loot table), `EpicSiegeCompat`, `TwilightForestCompat`, `NpcItemPropertiesClient`.

## Fixes of known bugs of the original

- `TeamData`: the 1.12.2 save built the "recently left teams" list and threw it away, so after a restart leaving a team with a bad standing wiped it at once.
  It is saved and loaded now (`playerLeavingTeams`). Said in the class comment.
- `NpcSkinSettings`: the buffer reader read the skin string with limit 60 where the writer allows 100 (class comment).

## Not ported

- Electroblob's Wizardry compat (`NpcFactionSpellcasterWizardry`, `EBWizardryCompat`, the `spells` keys of the defaults, container 48): dropped by decision. The
  plain faction spell caster stays; its `enabled` flag is false in the data for every faction, as in 1.12.2.
- `npc/datafixes/*` (1.12.2 world data fixers): not applicable.
- `PacketStructureEntry` (registered by this module in 1.12.2, belongs to Structures). `PacketExtendedReachAttack` is kept as `ExtendedReachAttackPayload`, but 1.21 already
  checks attacks within the player's entity interaction range, so it is only needed for a client that ray traces further; the held weapon check became a range check.
- The unregistered `headquarters` and `teleport_hub` block assets, the `textures/blocks/npc/teleport_hub_*.png`, `TileRecruitingStation` (never registered).
- The four coin items share the single 1.12.2 coin texture and model (`coin.png`); the metal only changed the name.
- Translations other than en_us.
- Entity render slice items that were not needed here: `textures/entity/npc/` is copied only because `NpcSkinSettings.BASE_DEFAULT_TEXTURE` needs `npc_default.png`.

## API names I could not confirm

- `Mob`/`EntityType` and loot API names used here were all checked in the sources. Not checkable: Epic Siege Mod's 1.21 target goal class (`EpicSiegeCompat`,
  TODO(port)) and whether the Twilight Forest dimension id is `twilightforest:twilight_forest` in its NeoForge release.
- `NearestAttackableTargetGoal.targetType` is a protected field read by reflection in `NpcEventHandler` (found as the only non-static `Class` field); not run.
- The `minecraft:custom_data` recipe result written as a compound in `spawner_*.json` relies on `CustomData.CODEC` (compound or SNBT string) - checked in the sources.
- Item stack JSON of trade lists (`id`, `count`, `components`) follows `ItemStack.CODEC` of 1.21.1; component JSON such as `minecraft:enchantments {"levels": ...}`,
  `minecraft:dyed_color {"rgb", "show_in_tooltip"}` and `minecraft:banner_patterns` was written from memory of the 1.21.1 formats and is the first thing to check if
  trades are dropped at load (they are only decoded when a trader opens, so nothing fails at startup).

## Rework candidates (not done, for step 4)

- 1.12.2 saved edited trade lists by rewriting the data file in the config folder; `FactionTradeListRegistry.saveTradeList` still does that
  (`config/ancientwarfare/registry/npc/faction_trade_lists.json` wins over the data pack file). A data pack override or a saved data object would be cleaner.
- Faction standings and teams are keyed by player name, as in 1.12.2; UUIDs would survive renames.
- The three unused town hall fields (`isNeglected`, `oldOwner`, `name`) and the `heal_per_try` attribute are kept for file compatibility only.
- Spawner icons through `custom_model_data` could be replaced by a dedicated item model property or the 1.21.4+ item model system.
- `starting_faction_standings` and `food_values` are `"name=value"` string lists in the config because a spec cannot grow keys; a datapack-driven food table would suit better.
- The skin index has 1,768 "custom" skins (every file that the old `skin_pack.meta` did not list); the old meta had 58 entries pointing at missing files (not loaded in 1.12.2 either).
- Faction NPCs whose loot tables are empty (`minecraft:empty`) or that name `ancientwarfare:chests/*` need the Structures data slice's chest tables to exist.
